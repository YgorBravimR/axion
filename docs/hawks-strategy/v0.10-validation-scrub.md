# v0.10 Validation Scrub (Phase J)

Pre-flight for the 10-day scrub Ygor signs off on per the exit-management spec §11.

## What's wired

The engine lab at `/dev/hawks-engine-lab` now has:

- Three real playbooks firing (mean_reversion, retracement, vwap_rejection) gated by 60m direction + VB + leg-shape + 5m HH/LL + gate-stability.
- Per-fire exit lifecycle simulator across 8 modes:
  - Conservative (Mode 1, static 3R, no trail) — default toggle
  - Moderate (Mode 2, run-forever trail after 3R)
  - Fibo T1 / T2 / T3 (Mode 3a) — measured-move 76.4 / 100 / 161.8%
  - Fibo T1 / T2 / T3 + trail (Mode 3b)
- Chart overlay of T1/T2/T3 + retracement-peak anchor when in any Fibo mode, scoped to the active day.
- Universal breakeven primitive — stop moves to entry on net favor ≥ 1R (= 2 × renkoSize) on a favorable brick close.
- Trail-after-3R primitive — stop ratchets `close ± 2 × renkoSize` on every favorable brick close after net favor ≥ 3R.
- Cursor-reactive badge row (gate, MACD, EMA, VWAP, pivot bias).

## Known caveats before the scrub

1. **H/I produce zero fires in the current lab view.** The universal entry gates were calibrated against `mean_reversion`'s VB-style snap-back shape. `retracement` and `vwap_rejection` need per-playbook gating before they fire under the lab's filters. See `docs/gotchas.md` → "lab's universal entry gates over-filter retracement / vwap-rejection fires". Work-around for the scrub: validate H/I logic via the unit tests (`pnpm vitest src/__tests__/lib/backtest/{retracement,vwap-rejection}-playbook.test.ts`) until per-playbook gates land.
2. **Demo fires still emitted** on bricks that pass lab gates but produce no real playbook fire. Distinguish them by the `demo:<dir>` label; remove via the `DEMO_FIRES` switch in the lab action when ready.
3. **Per-playbook engine switcher not yet in the lab UI.** `processHawksSinglePlaybookCandle` is implemented but the lab still shows the multi-orchestrator output. Per-playbook lab toggle is part of the same per-playbook-gate work.

## Acceptance criteria (spec §11)

Pass = Ygor's exact quote, _"On every day I looked, the entries are correct."_

Specific checks during the scrub:

1. **Every fire's breakeven event** is visible on the chart (stop moves to entry at exactly 2 favorable bricks). Verify with the cursor badge.
2. **Every Mode 3 fire has a visible Fib overlay** at fire time, anchored correctly to the 15m last impulse.
3. **Every trail-after-3R event** shows the moment of activation (6 favorable bricks = 3R) and the stop ratcheting on each subsequent brick close.
4. **Per-playbook view** in the lab shows ONLY that playbook's fires; the integrated view shows all three with no contamination.
5. **No false-positive fires** from chop / noise — the existing entry gates plus `mean_reversion`'s intentional chop firing are visually distinguishable from `retracement` / `vwap_rejection` that should reject chop.

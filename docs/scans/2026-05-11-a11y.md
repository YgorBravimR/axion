## Phase 5a — key insight on `<Label id="label-X">` pattern

The custom `Label` primitive at `src/components/ui/label.tsx` declares `id: string` as **required** in its props. The intent appears to have been: "use this id from `aria-labelledby` on the corresponding control." But across the codebase, ~95% of the `id="label-X"` values are dead weight — only **5 controls** actually reference them via `aria-labelledby`:

- `journal/trade-form.tsx`: `label-trade-direction`, `label-trade-setup-rank`, `label-trade-followed-plan`
- `journal/trade-info-notes-tab.tsx`: `label-panel-followed-plan`, `label-panel-rating`

For the rest, the `id="label-X"` was added in habit-driven shorthand expecting screen-reader linkage that never materialized. **The correct link mechanism is `htmlFor` (which the Label primitive accepts via `...props` to `LabelPrimitive.Root`).** A native `<label id="...">` does not link to anything; only `<label for="...">` does.

### Why a codemod can't fix all 71 in one shot

The label-id → input-id naming is inconsistent. Three real patterns observed:

1. **Strict match** (`label-X` → input `id="X"`) — safe to rewrite. _25 hits._
2. **Scoped match** (`label-startTime` → input `id="orb-startTime"`, `label-zero-cross` → switch `id="dezk-zero-cross"`) — requires reading the actual sibling id. _3 hits manually fixed._
3. **No DOM target** — Label decorates a readonly `<div>` display (`csv-trade-card.tsx` PnL/MFE/MAE/entry-price), wraps a custom component without an inner `id` (`RadioGroup`, `RatingInput`, `StarRating`), or is followed by a tooltip wrapper id. _43 hits — each needs human triage._

The strict-only codemod (`scripts/label-htmlfor-fix.ts`) was kept conservative on purpose: a false `htmlFor` (pointing to a tooltip wrapper or a non-existent id) is worse than no `htmlFor` because it actively misinforms screen readers.

## Phase 5c — prevention rules (memory seed)

### New anti-patterns to log

1. **`<Label id="label-X">` is not a link to anything.** Screen readers only follow `htmlFor` (or DOM nesting). Adding an `id` to a `<label>` is useful only when a separate control wires `aria-labelledby="label-X"`. Default to `htmlFor`. The codebase has 5 legit `aria-labelledby` usages and ~150 dead `id` decorations.

2. **`FormLabel` is the safe path** — it wires `htmlFor` automatically via `useFormField`. New forms should prefer it unless they need the lower-level primitive for explicit reasons.

3. **`label-X ↔ X` is not a project convention.** Inconsistent naming (`label-startTime` → `orb-startTime`, `label-zero-cross` → `dezk-zero-cross`, `label-csv-strategy` → `csv-trade-strategy`) makes a blind codemod unsafe. Future fixes need per-file inspection or a stricter convention enforced by code review.

4. **A wrong `htmlFor` is worse than no `htmlFor`.** Pointing to a tooltip wrapper id or a non-existent id actively misleads assistive tech. When the target is unclear, prefer skipping over guessing.

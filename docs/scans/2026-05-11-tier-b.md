## Phase 5a — system-wide solutions hide per-component detector noise

Two patterns in the codebase do work that per-component audits can't easily detect:

### 1. Global reduced-motion guard (`globals.css:1089-1109`)

```css
@media (prefers-reduced-motion: reduce) {
	.animate-transition-scale-in,
	.animate-transition-text-up,
	.animate-transition-ring-pulse,
	.animate-overlay-fade-out,
	.animate-overlay-pulse-line {
		animation: none !important;
	}

	*,
	*::before,
	*::after {
		transition-duration: 0.01ms !important;
		animation-duration: 0.01ms !important;
		animation-iteration-count: 1 !important;
		scroll-behavior: auto !important;
	}
}
```

The comment captures the intent: "Global guard: nuke all transitions + animations so any future utility (`transition-colors`, `transition-transform`, transform/scale hover, etc.) respects the OS-level preference without per-component motion-reduce audits. WCAG 2.3.3 (Animations from Interactions)."

The per-component `motion-reduce:animate-none` you see in components like `src/app/loading.tsx` is belt-and-suspenders — useful for documentation but redundant with the global guard. The detector `rg -n 'animate-' src/components | rg -v 'motion-reduce'` therefore reports 251 hits that are all already covered.

### 2. Error boundary i18n cascade

- `src/app/error.tsx` (root): hardcoded English. Runs before `[locale]` segment resolves → no `NextIntlClientProvider` in tree.
- `src/app/global-error.tsx`: hardcoded English. Same reason; also wraps the `<html>` element itself.
- `src/app/[locale]/error.tsx`: fully i18n'd via `useTranslations("errors.boundary")`.

The rule: **i18n is only available below the locale layout boundary.** Framework error files that live above it must be hardcoded; flagging them as "missing i18n" is a false positive.

## Phase 5c — prevention rules (memory seed)

### Global solutions beat per-component audits

When you find a system-wide solution (CSS global guard, root-level i18n boundary, custom ESLint rule), audit-time detectors that look at per-component code will return noise. Always grep for the _system_ solution first:

- `rg -n 'prefers-reduced-motion' src/app/globals.css` — does a global reduced-motion guard exist?
- `find src/app -name 'error.tsx' -o -name 'loading.tsx'` — boundary inventory before audit
- `cat eslint.config.mjs` — what's already enforced?

If a system-wide solution covers the bug class, the per-component detector is irrelevant.

### Inline arrow handlers vs named `handle*` is style, not correctness

CLAUDE.md says "event functions should be named with a `handle*` prefix". Spirit: when you _declare_ a handler, name it `handleClick`/`handleSubmit`/etc. Don't apply to:

- Trivial inline forwarders: `onClick={() => onSelect(x)}` — extracting a `handleSelect` adds no clarity
- Trivial state-setters: `onChange={(e) => setX(e.target.value)}` — same
- Prop pass-throughs: `onClick={reset}` — already named at the source

Apply to: handlers with non-trivial logic that re-renders on each parent render (memoization wins) or repeats across the file.

### Error-boundary i18n cascade

- `src/app/error.tsx` + `src/app/global-error.tsx`: pre-locale → hardcoded English.
- `src/app/[locale]/error.tsx`: post-locale → `useTranslations` works.
- Same rule for any other framework boundary that lives above the locale segment.

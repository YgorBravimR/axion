Scan target: math deviation, wrong calculations, misleading data sources, duplicate sources across the daily/weekly/monthly/quarterly/annual planning fractal. Goal: trader can trust every number 100%.

**Headline validation**: the in-flight `real-carry-forward.ts` change was independently audited and confirmed correct. The old `compound-projection.ts` model compounded _planned_ goals into capital instead of actual P&L — a worked example showed **37.8% capital inflation after one losing month** ($100K init, plan +$30.8K net assumed vs real −$5K → $130.8K vs $95K), cascading into inflated 1R, inflated goals, and delayed tier downgrades. The new model threads `initialCapital + Σ(realized P&L per month, net of profit-share → IR tax → withdrawal)`. Month, quarter, and year views now reconcile on every headline number (capital, 1R, goals, realized P&L, assertivity, tax rate) — all through single shared functions.

## Root causes

**1. Silent-NaN money paths (findings 1, 2, 4, 8, 11, 14).** Drizzle numeric/decimal columns come back as strings; the codebase converts them at ~20 call sites with bare `parseFloat()`/`Number()` and no finiteness guard. NaN is truthy, survives `Math.max/min` clamps, and propagates silently through multiplication chains into displayed goals and risk thresholds — it manifests only at runtime with corrupt/unexpected DB data, never at write or build time, which is exactly why it kept passing review. The worst instance (drawdown-trigger) fails _silently in the dangerous direction_: the tier never downgrades after losses. Anti-pattern signature: `(parseFloat|Number)\(` on a DB-sourced value without `Number.isFinite` within 3 lines.

**2. Compounding planned instead of realized values (validated in-flight fix).** The original projection design compounded planned goals into capital because realized P&L wasn't plumbed at design time. It manifests only across month boundaries with a missed target — invisible in demos and single-month tests. Class rule: any value that _carries forward_ across periods must derive from realized data, with planned data used only for forward projection and labeled as such.

**3. Derived numbers displayed without provenance (findings 3, 6, 10).** The resolver tracks provenance internally but components dropped it before render, so real, snapshot, cascaded, and manual values all looked identical. Slipped review because each component individually "shows the right number" — the failure is only visible when the trader asks "where did this come from?" Signature: a money/R value rendered from a resolver/cascade result with no accompanying provenance prop.

**4. Copy-paste between the month and quarter report pair (findings 1, 9, and equivalent-but-duplicated tax math in 15).** `month-report.tsx` and `quarter-report.tsx` evolve in lockstep by duplication; every bug in one appears in the other, and formulas can drift. Signature: identical function bodies in both files.

## Prevention rules

- **Rule**: Every `parseFloat`/`Number()` on DB-sourced or user-sourced values must go through `parseFiniteNumber`/`parseFiniteOrNull` (`src/lib/fractal-plan/parse-number.ts`) or carry an explicit `Number.isFinite` guard.
  **Detector**: `rg -n 'parseFloat\(|Number\(' src/lib/fractal-plan/ src/components/fractal-plan/ src/app/actions/fractal-plan/ | rg -v 'isFinite|parseFiniteNumber|parseFiniteOrNull|Number\.'`
  **Auto-fix**: manual (route through parse-number.ts)
- **Rule**: Validate finiteness BEFORE clamping — `Math.max/min` are NaN-transparent.
  **Detector**: `rg -n 'Math\.(max|min)\(' src/lib/fractal-plan/ -A2 -B4 | rg 'parseFloat'`
  **Auto-fix**: manual
- **Rule**: Values that carry forward across periods must derive from realized data (`real-carry-forward.ts`), never from planned goals; planned data only projects forward and renders `text-proj italic`.
  **Detector**: `rg -n 'snapshotOneRCents|plannedGoal.*capital|goal.*compound' src/`
  **Auto-fix**: manual review
- **Rule**: No `as string[]` (or any `as`-cast) on JSONB columns — runtime `Array.isArray` guard required.
  **Detector**: `rg -n 'as string\[\]' src/lib/ src/app/actions/`
  **Auto-fix**: manual
- **Rule**: One format per quantity type: R = `.toFixed(1)` + `R` (± prefix when realized); no mixing compact/full BRL within one card group; projected = `text-proj italic`, projected losses = `text-loss italic`.
  **Detector**: `rg -n 'toFixed\(2\)\s*\+?\s*.?R|toFixed\(0\).*R"' src/components/fractal-plan/`
  **Auto-fix**: /normalize
- **Rule**: Cents arithmetic stays integer — wrap float products in `Math.round` before add/subtract with cents.
  **Detector**: `rg -n 'Cents\s*[-+]\s*\w+\s*\*' src/lib/`
  **Auto-fix**: manual

## Methodology

Subject-first horizontal sweep. Goal: find user-facing strings that bypass `next-intl` despite the project having mature locale infrastructure (`pt-BR` + `en`, 4683-line message files, 40+ namespaces).

### Infrastructure baseline

- **Library**: `next-intl@4.11.0`
- **Default locale**: `pt-BR` (Portuguese), fallback for all unmatched headers (`localeDetection: false`)
- **Secondary**: `en`
- **Message files**: `messages/en.json`, `messages/pt-BR.json` (parallel keys)
- **Usage pattern**: `useTranslations("ns")` for client components, `getTranslations("ns")` for server components / actions
- **i18n adoption ratio**: 254 of 753 `.ts`/`.tsx` files (~34%, but counting libs/types — real ratio in user-facing components is higher)

## Root Causes

**RC-1: New feature surfaces built without i18n scaffolding.** The fractal-plan cockpit landed as a vertical slice without ever wiring `useTranslations`. Once one file in a feature folder lacks the hook, copy-paste propagates the pattern. 16/16 cockpit files affected.

**RC-2: aria-labels routinely written in raw PT.** Developers write the aria-label in whichever language is on screen at the moment. Without a lint rule banning literal `aria-label`, it slips through review every time.

**RC-3: PDF templates treated as "internal output", not UI.** `lib/pdf/*` lives outside `components/` and isn't reflexively touched during i18n passes. But the PDF is a user deliverable — should be locale-aware.

**RC-4: Editor placeholders are long, opinionated copy.** Designers wrote them in English early, no one extracted later — they read like comments, not UI strings.

## Prevention rules (seeded for memory.md)

- **Banned: literal `aria-label="…"`** in `src/components/**` and `src/app/**`. Required pattern: `aria-label={t("key")}`. Detector: `rg -n 'aria-label="[A-Za-z]' -g '*.tsx' -g '*.ts' src/components/ src/app/`
- **Banned: literal `placeholder="…"`** of more than one word. Single-word labels representing field names (e.g., `placeholder="Ativo"`) are still banned — extract them. Detector: `rg -n 'placeholder="[A-Z]' -g '*.tsx' src/components/ src/app/`
- **Banned: JSX text nodes that are >1 capitalized word** in user-facing components. Detector: `rg -n '>\s*[A-Z][a-z]+(\s+[A-Za-z]+)+\s*<' -g '*.tsx' src/components/ src/app/`
- **Banned: literal `title="English/Portuguese"`** on JSX elements. Detector: `rg -n '\btitle="[A-Z]' -g '*.tsx' src/components/ src/app/`
- **Internal-only**: `throw new Error("...")` exempted; these are caught and reformatted. Do not lint.
- **PDF templates (`lib/pdf/**`)** must use `getTranslations()` from the calling server action's locale, not be hardcoded.

These detectors should be added to `/scan` Phase 0 pre-flight so vertical scans of `journal`, `command-center`, `analytics` catch new offenders before they accrue.

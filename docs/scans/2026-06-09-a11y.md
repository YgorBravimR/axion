## Root Cause Clusters

### 1. **Deferred Label ↔ Control Linkage (20+ instances)**

**Pattern**: Custom form components in `journal/` and `backtest/` use `<Label id="label-X">` without `htmlFor` wired to the control. This is a continuation of the 2026-05-11 audit's Phase 5c deferred list.

**Why it slipped**: The prior scan identified the pattern but deferred fixes for custom-component cases (AssetCombobox, RatingInput, RadioGroup, etc.) because the target input id is not a direct sibling `<Input>`. Without per-file inspection, a codemod can't safely wire `htmlFor`.

**Manifest time**: Runtime — screen reader announces the field label, but the _association_ is broken; users don't know the label refers to the specific control.

**Grep detector**:

```bash
rg -n 'id="label-[^"]+' src/components/journal src/components/backtest | \
  xargs -I {} bash -c 'f="$(echo {} | cut -d: -f1)"; id="$(echo {} | cut -d: -f3- | grep -o "label-[^\"]*" | head -1)"; \
  grep -q "htmlFor=\"${id#label-}\"" "$f" || echo "{}"'
```

**Auto-fix**: Manual. For each deferred item, inspect the control and add `htmlFor`. Pair with `/clarify` to verify the label text is also semantically correct.

---

### 2. **Missing Focus Trap & Restoration in Dialogs**

**Pattern**: `src/components/ui/dialog.tsx` and `src/components/ui/alert-dialog.tsx` delegate focus management entirely to Radix primitives. Radix _does_ trap focus and restore it, but the component doesn't expose a hook for custom focus restoration (e.g., to auto-focus a specific button on open).

**Why it slipped**: Radix's focus management is correct by default, but if a page uses multiple dialogs or async content loading, the auto-restored focus may not land on the intended element.

**Manifest time**: Runtime — keyboard users open a dialog, tab inside, close it; focus returns to the trigger (correct). But if the trigger was removed or re-rendered, focus may land on `<body>`.

**Grep detector**:

```bash
rg -n 'DialogContent|AlertDialogContent' src/ --max-count=20 | \
  xargs -I {} bash -c 'f="$(echo {} | cut -d: -f1)"; \
  grep -q "initialFocus\|autoFocus" "$f" || echo "Missing focus target: {}"' | head -5
```

**Auto-fix**: Use `/harden` to add explicit focus management: `useEffect(() => { dialogTrigger?.current?.focus() })` on close, or configure Radix with `initialFocusRef`.

---

### 3. **Color Contrast on Muted Text + Secondary Backgrounds**

**Pattern**: App-shell and sidebar use `text-txt-placeholder` on `bg-bg-200` / `bg-bg-300` backgrounds. Token names suggest "placeholder" (disabled, muted), which typically has lower contrast. No explicit WCAG AA verification in design tokens.

**Why it slipped**: Design tokens are defined semantically (by purpose), not by WCAG ratio. The token definitions in `src/app/globals.css` don't document contrast guarantees.

**Manifest time**: Runtime — low-vision users or mobile screens in bright sunlight may not distinguish placeholder text from background.

**Grep detector**:

```bash
rg -n 'text-txt-placeholder' src/components/layout src/components/settings | \
  wc -l && echo "instances of muted text — should all have contrast audit"
```

**Auto-fix**: Run `/colorize` on the layout components to verify `text-txt-placeholder` meets 4.5:1 AA when paired with its background token. If not, upgrade to `text-txt-200` (standard secondary text).

---

### 4. **Breadcrumb & Page Navigation Missing ARIA Semantics**

**Pattern**: `src/components/layout/page-breadcrumb.tsx` renders breadcrumbs without `aria-label="Breadcrumb"` on the `<nav>` and without `aria-hidden="true"` on visual separators (chevrons, slashes).

**Why it slipped**: Breadcrumbs are less critical than primary navigation, so they weren't flagged in the prior scan's hotspots (journal/new, command-center).

**Manifest time**: Runtime — screen readers announce breadcrumb items individually; separators are redundantly announced, cluttering the navigation experience.

**Grep detector**:

```bash
rg -l 'breadcrumb|Breadcrumb' src/components | \
  xargs rg -n 'aria-label.*[Bb]readcrumb' || echo "Breadcrumb missing aria-label"
```

**Auto-fix**: Use `/clarify` to add `aria-label="Breadcrumb"` to `<nav>` and `aria-hidden="true"` to chevron separators.

## Notable Strengths

1. **Skip link is present and visible on focus** — app-shell.tsx has a well-implemented "Skip to content" link that appears on `focus:not-sr-only`. This is exemplary.

2. **Keyboard navigation is solid** — no `role="button"` on `<div>`, no click handlers on non-interactive elements. Lint is enforcing this (jsx-a11y/no-static-element-interactions).

3. **aria-live regions are widely used** — forms, alerts, and imports properly use `aria-live="polite"` or `aria-assertive"` for dynamic content. Screen readers will announce changes.

4. **Focus-visible styling is consistent** — Most interactive elements have `focus-visible:ring-2 focus-visible:ring-acc-100`, providing strong keyboard indicators.

5. **Semantic landmarks are correct** — `<header>`, `<nav>`, `<main>` are in place. Sidebar toggles and responsive behavior are properly marked.

| **Custom form controls (Combobox, Rating, Radio) must expose `aria-label` or `aria-describedby`.** | `rg -l 'AssetCombobox\|RatingInput\|CustomRadio' src/ \| xargs grep -L 'aria-label\|aria-describedby'` | `/clarify` per component                     |
